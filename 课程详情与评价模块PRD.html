课程详情 · 教师介绍 · 往期学生评价（在现有选课系统中增强信息展示，不改变选课交易流程）
版本 v0.1（待评审）日期 2026-10-24 模块名称（暂定）：选课参考信息模块文档负责人：[TBD]

1背景与目标

1.1 背景

已确认事实：当前选课阶段，系统仅向学生展示课程名称，缺少课程内容简介、授课教师介绍、往期同学评价等决策信息，学生选课参考信息不足，容易出现所选课程与自身预期差距较大的问题。

选课期学生只能看到课程名称 → 无法判断课程内容、考核方式、工作量与教师风格 → 凭课程名或传闻做决策 → 实际课堂与预期差距大（退改选、试听后流失、满意度低等表现假设 TBD）

本模块的产品回应：在学生提交选课决策之前，在同一选课系统内提供结构化的课程介绍、教师介绍与可信赖的往期评价；并让信息随每学期课程开设持续更新。

1.2 产品目标

产品目标（正式表述） 优化学校现有选课机制，补充课程与教师信息展示能力，帮助学生在选课阶段获取更完整参考资料，减少选课预期偏差。

该目标拆解为四个产品方向，全部通过在现有选课系统内增强信息展示实现，不新增独立的选课交易流程：

目标方向含义
① 优化现有选课机制不另建系统、不改变容量/抽签/退改选等既有选课规则，仅在现有选课列表与决策环节补齐信息入口
② 补充课程信息展示内容简介与大纲、考核方式与成绩构成、先修要求与适配建议、课外工作量
③ 补充教师信息展示教师背景、研究方向、教学风格，并提供往期学生评价与教师回应
④ 减少预期偏差让学生选前预期与实际课堂一致：学什么、怎么考、投入多少、是否适合自己，均可提前获知

目标达成的可观察信号（验收时可直接核对，非口号）

  • G1（对应②④）：学生在提交选课前，可在同一页面查看课程内容与大纲、考核方式与成绩构成、先修与适配建议、授课教师介绍，以及已修读学生的评分、标签与评语。
  • G2（对应③，可信前提）：每条评价仅来自实际修读完该课程班次的学生；学生可选择匿名；姓名、学号在任何公开页面均不出现。
  • G3（对应③，可信前提）：不当评价内容在发布前被自动拦截或发布后被及时下架，学生可举报，处理结果可反馈；教师可对已发布评价做出一次公开回应。
  • G4（对应①，持续运转）：教师可按学期维护本人课程介绍与个人介绍；无教师维护内容的课程有明确占位与教务补录路径，不出现空白页。
关于量化目标「减少选课预期偏差」是方向性结果，本 PRD 不杜撰指标数值。是否以「因不了解课程导致的退改选比例」「课程详情页查看率」「选课期人均查看详情课程数」等作为上线后衡量指标，由教务在评审时确认（见第 6 节 Q10）。

1.3 范围与边界

最小完整旅程（P0）

  • 入口条件：学生在选课开放期进入现有选课系统（沿用现有登录与身份）。
  • 完成 P0 所需动作：
    1. 在选课列表看到课程的评分、标签与一句话简介；
    2. 进入课程详情，查看「课程介绍 / 授课教师 / 学生评价」三类信息；
    3. 信息不足时有明确的空状态（而非空白）；
    4. 课程结束、成绩发布后，修读学生收到评价邀请并提交评分与评语；
    5. 评价经审核后对后续选课学生公开展示；教师可回应；学生可举报，管理员可治理。
  • 完成证据：学生浏览详情后，仍通过现有选课操作完成选课；评价提交者可看到自己评价的审核状态（待审核 / 已发布 / 需修改）。
  • 最重要失败的恢复路径：评价被审核驳回时，系统给出具体原因类别，学生修改后可重新提交，无需重填全部内容。

P1（本期不做，仅登记）

  • 多课程横向对比、选课问答区（向教师/学长提问）、「评价有用」投票与按有用度排序；
  • 基于培养方案/兴趣的课程推荐与适配度打分；教师数据看板（评分趋势分析）。

明确不做（范围外）

  • 选课交易本身：课程容量、志愿/抽签、时间冲突检测、抢课、退改选操作均沿用现有选课系统，本模块只做信息展示与评价。
  • 教务匿名评教：评教数据面向管理、不公开；本模块的评价面向后续选课学生公开展示。两者数据隔离，是否互相引用见 Q8。
  • 成绩查询、考勤、课堂互动等教学环节功能。

2角色与核心对象

2.1 角色

角色定义核心诉求
选课学生当前处于选课开放期、尚未修读该课程的学生选课决策前获得充分、可信的参考信息
修读学生已修读完某课程班次且成绩已发布的学生（由"选课学生"转化）匿名、低负担地分享真实体验
授课教师当前或历史学期某课程班次的任课教师准确介绍课程与自身、对误解性评价作出回应
教务管理员院系/学校教务内容管理人员保证信息完整与内容合规，处理审核与举报
系统自动审核按敏感词与规则自动处理评价的程序角色拦截明显违规内容、分流可疑内容到人工

2.2 核心对象

对象说明关键字段（产品层面）
课程班次 Section某学期开设的某门具体课程，绑定一名授课教师（合班多教师情形见第 5 节）。评价挂在班次上，聚合到课程学期、课程名、授课教师、学分/学时、上课时间（沿用现有系统）
课程介绍 CourseProfile教师按班次维护、经审核发布的课程信息内容简介、教学目标、课程安排/大纲附件、考核方式与占比、先修要求与适配对象、更新学期；状态：待审核 / 已发布 / 已驳回

2.3 评价生命周期（统一状态机）

状态进入条件谁可见允许的转移
草稿学生开始填写但未提交（自动保存）仅本人提交 → 待审核；删除 → 消失（不保留）
待审核学生提交评价本人（提示审核中）、管理员自动/人工通过 → 已发布；命中规则可修改 → 需修改；明确违规 → 已隐藏
需修改命中可修正类规则并被驳回，附原因类别仅本人 + 管理员修改后重提 → 待审核；学生放弃 → 保留为草稿 假设 TBD
已发布审核通过全部用户（按匿名规则展示）评价窗口期内学生撤回 → 草稿；举报成立/管理员下架 → 已隐藏
已隐藏违规判定成立或多人举报触发自动隐藏管理员；本人可见"已隐藏及原因"管理员复核恢复 → 已发布；维持隐藏（P1 提供学生申诉入口）
窗口期规则（一处定义，全局引用）评价开放窗口为「该班次成绩发布后 [TBD：建议 14 天]」至「下一学期选课开始日」。窗口期内学生可编辑或撤回自己的已发布评价（编辑后重新进入待审核）；窗口期关闭后评价只读，不可再提交。

3功能需求

P0 共 8 个功能模块。每个模块给出目的、触发、处理规则、结果与状态变化、权限与异常；交互复杂的模块附可点击原型，原型标签与正文术语一致。

P0FR-01

选课列表信息增强与详情入口

让学生在浏览可选课程清单的第一屏就获得决策线索，并能一键进入完整详情。

触发：学生在选课开放期进入现有选课列表页。

展示规则：每一行课程在现有信息（课程名、教师、上课时间、容量状态）之外，新增：

  • 综合评分（1–5 分，一位小数）；有效已发布评价不足 N 条（建议 5，[TBD]）时显示「暂无评分」，不显示数字；
  • 高频标签至多 3 个（取近两学期被选择次数最多者）；
  • 一句话简介：取该班次已发布课程介绍的开头约 60 字 假设 TBD；教师未维护时显示「课程介绍待补充」；
  • 新开课（无任何历史班次评价）显示「新开课」标记；
  • 统一的「查看详情」入口。

结果：点击行或「查看详情」进入 FR-02～FR-04 的课程详情页；选课按钮与现有系统完全一致。

权限：详情页全年可访问 假设 TBD；但「选课/退课」按钮仅在现有选课开放期可操作，非开放期置灰并提示开放时间。

P0FR-03

课程详情 · 授课教师介绍

让学生了解「谁来教、擅长什么、什么风格」，降低因师生风格不匹配造成的预期落差。

内容：头像、姓名、职称、院系（教务数据同步，教师不可改）；研究方向、教育背景、代表成果链接（选填）、教学风格自述与对选课学生的期待（选填）；该教师本学期开课列表与历史课程，可跳转对应详情页。

展示规则：教师自填内容需经审核发布（同 FR-07）；教务字段缺失时不显示该行；教师全部自填内容为空时，展示「教师暂未填写介绍」并保留教务基础信息，不生成空白标签页。

权限：教师仅可编辑本人介绍；合班课程按班次展示全部授课教师，每位教师只维护自己的部分。

P0FR-04

课程详情 · 学生评价展示

以聚合、可筛选、可追溯到真实修读者的方式呈现往期体验，同时保护评价人匿名。

页面结构：上方为聚合区（综合评分、四个维度得分、工作量分布、高频标签），下方为逐条评价列表与筛选器。

聚合口径（计算规则见 4.3）：

  • 综合评分与各维度分：仅统计已发布评价；不足 N 条（建议 5，[TBD]）时不显示数字评分，仅显示「评价不足，暂不显示评分」，评语仍逐条可见；
  • 四个维度：内容质量、讲授清晰、学习收获、考核合理，均为 1–5 分；
  • 课外工作量为独立口径（很少 / 较少 / 适中 / 较多 / 很多），以分布占比展示，不计入综合评分；
  • 高频标签按选择人数倒序，展示人数；标签库由教务统一维护（FR-08）。

聚合范围：默认聚合该课程跨学期、跨班次的全部已发布评价；当同一课程由不同教师开设时，提供「按授课教师」「按学期」筛选 口径假设，见 Q6。

P0 筛选与排序：按标签筛选（点击标签即过滤，可多选）、「只看有评语」；默认按学期由近及远、同学期按发布时间倒序。按有用度排序、关键词搜索为 P1。

单条评价卡片字段：匿名展示名（默认「选课学生（匿名）」；学生可选择公开年级/专业等非身份信息，永不公开姓名与学号）、修读学期、四个维度分、工作量、标签、评语（可为空）、发布时间、教师回复（FR-07，折叠在评价下方）、「举报」入口。

异常：评价被隐藏后立即从所有列表与聚合中剔除；筛选结果为空时显示「当前筛选条件下暂无评价」。

P0FR-06

评价审核、举报与内容治理

保证公开展示的评价真实、合规、对事不对人，同时给被评价的教师与其他学生救济入口。

3.6.1 发布前自动审核

  • 评价提交后先经规则引擎检查：违法违规词、广告或联系方式、人身攻击与侮辱性表述、无意义刷屏/重复字符。
  • 命中明确违规（违法、广告引流）→ 直接「已隐藏」，告知原因类别与《内容规范》链接；命中可修正类（攻击性表述、疑似联系方式）→ 「需修改」，附原因，学生修改后重提，不自动判死刑；疑似但不确定 → 进入人工审核队列。
  • 教师回复（FR-07）适用同一套规则。

3.6.2 发布后举报与下架

  • 每条已发布评价提供「举报」入口：举报类别必选（人身攻击 / 广告引流 / 与课程无关 / 抄袭代写信息 / 其他），文字说明选填；同一学生对同一评价只能举报一次，可在个人中心查看处理状态（已受理 / 已处理-已隐藏 / 不成立）。
  • 同一评价被 N 名不同学生举报（阈值 [TBD]，建议 3）时自动临时隐藏并进入人工复核；复核不成立则恢复展示，并通知举报人理由（不透露举报人身份）。
  • 管理员人工动作：通过、驳回（必选原因类别）、隐藏、恢复；全部操作留痕（操作人、时间、原因）。

3.6.3 隐私与身份边界（重要）

  • 学生公开侧：任何页面不出现评价人姓名、学号；匿名评价对教师和其他学生不可追溯身份。
  • 教师侧：教师看不到任何评价人的真实身份，也看不到「谁举报了评价」。
  • 管理员侧：仅在处理违规调查需要时可查看实名关联，查看动作留痕；是否需要双人审批见 Q4。
P0FR-07

教师端：信息维护与评价回复

让教师对课程信息负责、对争议评价有公开澄清渠道，而不是私下干预评价。

  • 课程介绍维护：每学期开课前（具体时间点由教务配置 [TBD]）教师按班次编辑 FR-02 全部字段，提交后进入「待审核」；审核通过后对学生发布；驳回时附原因，可修改重提。是否允许教师免审直发见 Q5。
  • 教师介绍维护：编辑 FR-03 自填字段，同样先审后发；教务同步字段只读，错误时引导联系教务更正。
  • 回复评价：仅可对「已发布」评价回复；每条评价最多 1 条教师回复，回复以教师真实姓名公开发布（不可匿名）；回复提交后走 FR-06 审核；发布后教师可在 [TBD：建议 30 天] 内编辑一次（重新审核）或删除（删除动作留痕，页面显示「教师已删除回复」或直接收起，二选一 [TBD]）。
  • 禁止行为（系统层面约束）：教师不能删除、折叠、排序学生评价，不能查看评价人身份，不能以加分/扣分等方式索取或交换好评（属线下管理规范，系统在提交页与教师端展示提示语）。
  • 消息触达：教师在其课程收到新的已发布评价时收到定期摘要（频率 [TBD：建议每周 1 次 digest]，避免逐条推送施压）；自己的回复/介绍审核结果实时通知。

4.2 数据归属与展示边界

  • 评价归属到课程班次；课程页默认按「课程」聚合。跨学期更换授课教师时，每条评价保留其原班次教师信息，学生可用「按授课教师」筛选。
  • 合班/多位教师授课：学生评价指向该班次；教师介绍页展示全部任课教师；学生不分别给多位教师打分（P0 不做教师维度拆分，见 Q6）。
  • 课程停开：已发布介绍与评价保留可见，列表中标注「本学期停开」，选课按钮置灰。

4.3 评分与标签聚合计算

  • 单条评价综合分 = 四个维度分的算术平均；课程综合评分 = 全部有效（已发布）评价单条综合分的算术平均，四舍五入保留 1 位小数。
  • 各维度分同理独立聚合；课外工作量为分类值，展示各选项人数占比，不参与平均。
  • 标签展示选择人数与占比；仅统计已发布评价；评价被隐藏/撤回后其评分、标签即时从聚合中剔除。
  • 不满 N 条（建议 5，[TBD]）：数字评分、维度分与标签人数均不展示；文字评价可逐条阅读，避免小样本误导。

4.6 内容规范（学生评价与教师回复共同适用）

  • 允许：基于自身体验的正负向评价、对教学内容与考核方式的具体批评、情绪表达；
  • 禁止：违法违规内容、广告与联系方式、针对师生的人身攻击/侮辱/造谣、代写代考等学术不端信息、与课程无关的刷屏内容、泄露他人隐私；
  • 争议处理原则：对课程苛刻可以，对个人攻击不行；观点性分歧（「我觉得作业太多」）不构成下架理由。
